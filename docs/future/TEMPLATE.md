# Plan title

| Field | Value |
| --- | --- |
| Status | Idea / Exploring / Planned / Implementing / Implemented / Superseded |
| Timing | Deferred |
| Area | Application area |
| Created | DD Month YYYY |
| Last reviewed | DD Month YYYY |
| Dependencies | None, or a short list |

## Plain-language purpose

Explain the problem and the intended outcome in terms a beginner can understand.

## Proposed changes

- Describe the important behaviour changes.
- Explain what will remain unchanged.
- Note any compatibility or migration requirements.

## Risks and safeguards

- Describe what could go wrong.
- State how the implementation will prevent or detect it.
- Include performance, data freshness, security, and multi-user concerns where relevant.

## Success criteria

- List measurable outcomes that prove the work helped.
- Include relevant response-time, reliability, correctness, or usability limits.

## Dependencies

List prerequisites, external services, deployment actions, or earlier work. Write **None** when there are no dependencies.

## Decisions and notes

Record important choices so they do not need to be rediscovered later.
